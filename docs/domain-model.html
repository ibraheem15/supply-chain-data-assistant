Current State

src/data/ contains two Python modules and one SQL script: ingest_supply_chain_dataset.py (Phase 1, complete), ingest_sop_pinecone.py (Phase 3a, complete — covers ingestion only: parsing, chunking, embedding, incremental sync. The RAG query tool, the text2sql tool, the resources/ application layer, and the agent orchestration are not built yet — see the last section below), and setup_security_and_view.sql (Phase 3b, complete).

DDD Concepts Applied Here

ConceptWhere

Anti-Corruption LayerLEGACY_COLUMN_NAMES — the single place mapping ubiquitous language to the legacy system's terse column names (IOT_TEMP_C)

Phase 3b: Agent Security Layer (SQL)

setup_security_and_view.sql is a SQL script, not Python, so there are no classes to diagram. What it creates inside SupplyChainDb:

ObjectRole
dbo.supply_chain_logisticsReal table with legacy column names; written only by the Phase 1 loader
ai.VW_SUPPLY_CHAIN_READINGSView over that table, columns renamed to the ubiquitous-language names
USR_FDE_RO (login + user)The agent's identity: SELECT on the view only, everything else denied

Dependency direction: USR_FDE_RO → ai.VW_SUPPLY_CHAIN_READINGS → dbo.supply_chain_logistics. The user has no path to the table except through the view (ownership chaining).

ConceptWhere
Anti-Corruption LayerThe view is the outbound counterpart of LEGACY_COLUMN_NAMES: the loader translates names in, the view translates them out. The mapping exists in both places and must be kept in sync
Least privilegeGRANT SELECT on one object; DENY on the dbo and ai schemas overrides any role or grant
Packages as layersSchema ai is the agent-facing layer, dbo the legacy layer

Planned, Not Yet Implemented

What's left to reach the design in research.md / technical-design-doc.html:

  • RAG query tool — take a user's question, embed it with the same model used at indexing time, search the Pinecone index, and return matched chunks with source metadata. Ingestion (above) does not include this.
  • text2sql tool — the structured data path, via MCP. The governed view and read-only user it will use exist (Phase 3b); the tool itself does not.
  • Application layer (resources/) — wraps both tools behind one interface the agent calls.
  • Agent orchestration — the LangGraph ReAct loop that decides which tool a question needs.

Until that code exists, this section stays a pointer, not a diagram.
